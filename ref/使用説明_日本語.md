# scomplex

他言語：[introduction_en.md](introduction_en.md) · [使用说明_中文.md](使用说明_中文.md) · [Mode_d'emploi_français.md](Mode_d'emploi_français.md)

scomplex は、互いに関連する三つの二次元代数——通常の複素数、分解複素数（双曲数）、および双対数——の上で演算するための小さなライブラリです。乗法の式はどこでも同じで、スカラー引数 `system` が代数を選びます。

同一の代数に対する言語移植は三つあります。

| 言語 | ファイル | 代数の選び方 |
|---|---|---|
| C | `scomplex.h`、`scomplex.c` | 明示的な `double system` 引数 |
| C++ | `scomplex.hpp`、`scomplex.cpp` | `complex<_Tp>::set_system` / `get_system` |
| Haskell | `Scomplex.hs`（モジュール `SComplex`） | 明示的な `Double` 引数。ほとんどの関数の第一引数 |

各移植は互いに、また元の C++ ソース `scomplex_no_throw.hpp` と一致することを意図しています。元版は「標準ライブラリの中に書いた」重ね合わせでした。`std::complex::experimental::zhangzl` に置き、通常の標準ヘッダを積み、**`<complex>` を `#include` しない**ことで `std::complex` と衝突しません。ここの C++ 移植もその重ね合わせを保ちます。キャンバス用 `no_throw` ビルドとの意図的な違いはエラー処理だけです。失敗経路は例外を握りつぶさず、実際に報告します。

超越関数は **`std::sin` / `atan2` / `std::polar` ではありません**。それらは通常の複素数（`i² = −1`）にしか成り立ちません。ここではライブラリ自身の乗法（冪級数、ニュートン法、算術幾何平均）で実装します。

Mode_d'emploi_français.md    フランス語

`scomplex.cpp.h` は誤った名前のヘッダで、削除済みです。C++ の呼び出し側は `scomplex.hpp` を含め、`scomplex.cpp` を **リンク** します。

利用者の functor を取るテンプレート（`differential`、`invert`、`integral`）は `scomplex.cpp` に移せません。functor の型は呼び出し側の翻訳単位でしか分からないからです。クラステンプレートとその他の自由関数テンプレートも同じ理由でヘッダに残します。

## 三つの代数

値は常に実成分の対 `(x, y)` です。乗法は

```
(x, y) * (u, v) = (x u + system * y v,  x v + y u)
```

| `system` | 代数 | 虚単位 | 平方 |
|---|---|---|---|
| `−1` | 通常の複素数 | `i` | `i² = −1` |
| `+1` | 分解 / 双曲 | `j` | `j² = +1` |
| `0` | 双対 | `ε` | `ε² = 0` |

C のマクロ：`SC_SYSTEM_COMPLEX`、`SC_SYSTEM_SPLIT`、`SC_SYSTEM_DUAL`。

C++ の既定は `complex<double>::_system = −1` です。静的メンバを読む演算の前に `complex<double>::set_system(+1)` または `set_system(0)` で切り替えます。Haskell の `defaultSystem` は `−1` です。

定義域判定に使う（代数的）ノルムは

```
norm(z) = x² − system * y²
```

`norm_norm(z) = x² + y²` はユークリッド長さの二乗で、`system` に **依存しません**。2 の冪による拡大縮小（`shift_left` / `shift_right`、C では `sc_shl` / `sc_shr`）は `norm_norm` を使い、ニュートン / AGM の引数を扱いやすい範囲に保ちます。

## エラー処理

エラーは本物です。捨てません。

| 移植 | 仕組み |
|---|---|
| C | `sc_last_error`（`SC_OK`、`SC_ERR_DIV_BY_ZERO`、`SC_ERR_OVERFLOW`、`SC_ERR_DOMAIN`、`SC_ERR_CONVERGENCE`、`SC_ERR_INVALID`）。`sc_set_error` が書き、`sc_peek_error` が読み、`sc_get_error` が読んで消す。`sc_error_string` がコードを文字列にする。 |
| C++ | `throw`。独自型 `complex_error`、`complex_division_by_zero`、`complex_overflow`、`complex_domain_error`、`complex_convergence_error` は `std::runtime_error` を継承。元版の一部経路は今も `std::domain_error` や `std::invalid_argument` を投げる（文字列コンストラクタ、`sqrt` の定義域）。 |
| Haskell | `ComplexError` の `throw`（`DivisionByZero`、`Overflow`、`DomainError String`、`ConvergenceError`、`InvalidFormat String`）。 |

`sc_last_error` はプロセス全体で一つのオブジェクトです（`scomplex.c` で定義）。C++ の `_system` と `print_number` はクラステンプレートの静的メンバなので、型ごとに一つ、プロセス全体で共有され、スレッド安全ではありません。外部ロックなしで同じ型に対して C / C++ ライブラリを並行呼び出ししないでください。

対を構築するときに溢れを検査します。非有限成分、または大きさが `max/2` を超える場合です（C では `DBL_MAX / 2`）。ゼロ除算は `|denominator| < ε` です。

## 算術と比較

加算、減算、符号反転、共役は `system` を使いません。乗算、除算、剰余は使います。

C の名前：`sc_add`、`sc_sub`、`sc_mul`、`sc_div`、`sc_mod`、`sc_neg`、`sc_conj`、および実数との混合補助（`sc_add_real`、`sc_mul_real`、`sc_div_real`、`sc_real_div` など）。

C++ は `complex<_Tp>` に通常の演算子（`+=`、`*=` など）を使います。剰余は商に `round_left`（`x - round(x)` 系の小数部）をかけてから掛け戻します。

比較は辞書式です。実部、次いで虚部。C：`sc_equal`、`sc_less` など。Haskell：派生の `Eq` のみで `Ord` インスタンスはありません。

**`abs` は成分ごと** で、`|x| + |y| i` であり、絶対値（モジュラス）ではありません。ユークリッド長さは `sc_modulus` / `sqrt(norm_norm(z))` です。これは原版どおりです。

---

## ビット演算と指数シフト

IEEE-754 のビット技は、原版が安価な 2 の冪スケールに使っていたため残しています。

- C：`sc_flnot` / `sc_flor` / `sc_fland` / `sc_flxor`（float）、`sc_dblnot` / `sc_dblor` / `sc_dbland` / `sc_dblxor`（double）、`sc_shift_left` / `sc_shift_right`（指数フィールドの加減）。
- C++：`digital_not` / `digital_or` / `digital_and` / `digital_xor`、`shift_left` / `shift_right`、`round_left`、`medium_mod`。
- Haskell：`scaleFloat` による `shiftLeft` / `shiftRight`。

有限の非零 double に対し、`shift_left(a, n)` は `a * 2ⁿ` で、指数ビットに `n` を足して実現します。ゼロはゼロのままです。これらは C の整数シフトでは **ありません**。

## 文字列解析

空白を除いたあと受け付ける形：

- 実部のみ：`3`、`-2.5`
- 虚部のみ：`i`、`+i`、`-i`
- 両方：`3+4i`、`3-4i`、`3+i`

C++ は `std::string` コンストラクタで正規表現を使い、不一致なら `std::invalid_argument` を投げます。C の `sc_from_string` は `SC_ERR_INVALID` を書いてゼロを返します。Haskell の `fromString` は `InvalidFormat` を投げます。

## 初等関数

いずれも `system` を取るか（C / Haskell）、`_system` を読みます（C++）。

### 平方根、立方根、整数乗根

指数シフトで `|z|` を `[0.5, 2]` に収めてからニュートン反復します。

- 実部が非負で虚部が零の平方根（および実立方根）は宿主の `sqrt` / `cbrt` を使います。
- `norm(z) < 0` なら **平方根は定義域エラー** です（通常の負の実数は `norm = x² ≥ 0` なので許され、分解の `sqrt(j)` は許されません）。
- 双対の `sqrt(−1)` は `norm = 1` なので定義域エラーでは **ありません**。反復は巨大な虚部を出し得ます。これが原版の挙動です。

初期値：右半平面では `1`。平方根ではそれ以外 `exp(i π / 6)`（または共役）。立方根では `exp(i π / 9)`。

### 指数関数

引数が実数なら宿主の `exp`。`norm_norm(z) > 1` なら `exp(z) = exp(z/2)²`（ライブラリの乗法）。それ以外は虚部の Horner 級数のあと `exp(real)` を掛けます。既定は 20 項です。

帰結：通常系では `exp(i π) ≈ −1`、分解系では `exp(j) = cosh 1 + j sinh 1`、双対系では `exp(ε) = 1 + ε`。

`polar(ρ, θ)` は `exp(log ρ + θ · unit)` で、この `exp` を使い、`std::polar` は使いません。

### 対数と偏角

`z = 0` または `norm(z) < 0` は定義域エラー。正の実数は宿主の `log`。それ以外は指数シフトで帯に収め（`ln 2` を加え）、AGM 恒等式を使います。

```
log(z) ≈ (π/2) * (1/AGM(1, q) − 1/AGM(1, z q))
```

`q` はごく小さい値です。既定は外側 40 段、AGM 8 段。`arg(z)` は `imag(log(z))` です。

### 余弦と正弦

余弦：実部を `2π` で剰余し、`norm_norm ≤ 1` まで半分にします（`cos 2α = 2 cos²α − 1`）。その後級数。既定 20 項。

**正弦は `cos(π/2 − z)`** で、原版どおり独立した級数ではありません。

`tan`、`cot`、`sec`、`csc` はそれらの比です。

### 双曲関数

```
sinh z = (exp(z) − exp(−z)) / 2
cosh z = (exp(z) + exp(−z)) / 2
```

および通常の比。逆双曲はいつもの log/sqrt 恒等式を、このライブラリの `log` と `sqrt` で評価します。

### 冪

整数の実指数は二進冪（`sc_pow_int`）。それ以外は `exp(log(base) * exponent)`。複素根は `exp(log(base) / exponent)`。指数が整数ならニュートン `root`。

## 逆三角関数

閉形式の `asin` 級数はありません。`acos` は `cos` のニュートン逆写像（`invert` / `sc_invert`）です。残りはその上の恒等式です。

```
asin(z) = π/2 − acos(z)
atan(z) = acos(1 / sqrt(z² + 1))
acot(z) = π/2 − atan(z)
asec(z) = acos(1/z)
acsc(z) = π/2 − asec(z)
```

**`atan(−1) = +π/4`** であり、`−π/4` ではありません。この恒等式は負の実軸で符号を落とします。移植の不具合ではなく原版です。

`invert` は各段で対象関数を二回微分し（有限差分二回）、更新の成分ごと `abs` が `10⁻³` を下回るか、`max_iterations`（既定 100）に達するまで続けます。微分が例外を投げると、C++ は `complex_convergence_error` を投げ直します。

---

## ガンマとベータ

Weierstrass 積で、既定 **100 000** 回（原版）。`Re(z) < 1/2` は反射公式、`Re(z) > 1` は漸化式。実軸上の非正整数は定義域エラー。`beta(a, b) = Γ(a) Γ(b) / Γ(a+b)`。

---

## 微積分

点 `a` での有限差分導関数：

```
d_real = (f(a + δ) − f(a)) / δ
d_imag = (f(a + i δ) − f(a)) / (i δ)
```

両者が食い違う（相対差の成分ごと `abs` が `> 10⁻³`）場合、複素微分可能ではないとみなします。C は `SC_ERR_DOMAIN` を書き、C++ / Haskell は投げます。一致すれば平均を返します。既定 `δ = 10⁻⁶`。

`a` から `b` の積分は左リーマン和で、刻みは `δ (b − a)`、条件は `δ · k ≤ 1`。既定 `δ = 10⁻⁶`。

C のコールバック型は `sc_func_s`：`sc_complex (*)(sc_complex, double system)`。C++ と Haskell は互換な functor / 関数を受けます。

---

## ハイパー演算と M / T / B

`hyper_xexp(z, n)` は `exp` を `n` 回（`n < 0` なら `log` を `|n|` 回）適用し、さらに `z` を掛けます。

`hyper_omega(z, n)` は `n ≥ 0` のとき `z` についてのニュートン逆写像（`invert`）です。負の `n` は `hyper_omega(z, −n)` にさらに `exp` を重ねます。

C は `sc_hyper_omega` が `sc_invert` を呼ぶあいだ、現在の `n` と `system` をファイル静的変数に置きます。C API が再入不可能なもう一つの理由です。

`M`、`T`、`B`（および C++ の配列一括オーバーロード）は原版のマンデルブロ風写像です。`M(a, c, f, L)` は `L` に応じて `a − f(a) + c` または `f(a) + c`。`T` は先に共役、`B` は先に成分ごと `abs`。`sc_square` / C++ 既定の `pow(x, 2)` はいつもの二次です。

## C++ 重ね合わせの詳細

```cpp
#include "scomplex.hpp"
using namespace std::complex::experimental::zhangzl;

complex<double>::set_system(-1.0);
complex<double> z(2.0, 1.0);
auto w = exp(z);
complex<double> i("i");
```

- 名前空間：`std::complex::experimental::zhangzl`。
- `std::complex` に対するように **`<complex>` を `#include` しない**でください。このヘッダは入れ子の `std::complex` 名前空間にすでに `complex` を定義しています。
- MSVC では `/utf-8` を付けてコンパイルします。ソースは UTF-8 です。このフラグがないと C4819 が出たり、`_system` の定義が食われて LNK2019 になったりします。
- `scomplex.cpp` をリンクします。無いと `shift_left` / `shift_right` / `round_left` / `medium_mod` が未解決です。
- MSVC では `COMPLEX_ALWAYS_INLINE` は `__forceinline` です。一部演算子の `inline` と重なると C4141 になりますが、リンクには影響しません。
- ノルムが負の `sqrt` は、原版どおり `"Square root of non-positive number"` の `std::domain_error` を投げ、`complex_domain_error` ではありません。

## C の詳細

```c
#include "scomplex.h"

sc_complex a = sc_make(2.0, 1.0);
sc_complex b = sc_make(1.0, 3.0);
sc_complex p = sc_mul(a, b, SC_SYSTEM_COMPLEX); /* -1 + 7i */
sc_error_t e = sc_get_error();
```

`scomplex.c` をコンパイルしてリンクします。C11 で足ります。C API を C++ から呼ぶための `extern "C"` があります。

`sc_get_error` はフラグを消します。消費せずに見るだけなら `sc_peek_error` です。

## Haskell の詳細

```haskell
import qualified SComplex as SC

let z = SC.fromRealImag 2 1
    w = SC.multiply SC.defaultSystem z (SC.fromRealImag 1 3)
```

ほとんどの演算は第一引数が `system` です。`add` / `subtract` / `conjugate` / `fromString` / `abs` は代数に依らないため例外です。

Prelude の `sqrt`、`exp`、`log`、`sin` などは hiding されています。`SComplex` か `qualified Prelude as P` を使ってください。

## 定数

C 関数 `sc_pi`、`sc_2pi`、`sc_pi_2`、`sc_pi_3`、`sc_e`、`sc_sqrt2`、`sc_sqrt1_2`、`sc_cbrt2`、`sc_cbrt1_2`。C++ は `complex<_Tp>` の静的メンバ（`pi()`、`e()` など）と `i()`。Haskell の局所名 `piVal`、`sqrt2` など。

## 残すべき原版の意味論

教科書の主値で採点するとバグに見えます。これが原版のライブラリです。

1. `abs` は成分ごとであり、モジュラスではない。
2. `sin(z) = cos(π/2 − z)`。
3. `atan(−1) = +π/4`。
4. 双対の `sqrt(−1)` は定義域エラーではない（`norm = 1`）。値は巨大になり得る。
5. 分解の `sqrt(j)` は定義域エラーである（`norm = −1`）。
6. ガンマは Weierstrass を 100 000 項使う。
7. 有限差分の逆写像は停止条件が `10⁻³` なので、逆三角は粗い。

## ビルド（MSVC / GHC）

ソースは UTF-8 です。

```text
cl /utf-8 /std:c11 scomplex.c your.c
cl /utf-8 /std:c++17 /EHsc scomplex.cpp your.cpp
ghc -i. YourMain.hs
```

GCC/Clang では `scomplex.c` または `scomplex.cpp` を呼び出し側と一緒にコンパイルします。C++ には例外が必要です（`-fexceptions`、通常は既定で有効）。C++ ヘッダは MSVC/GCC の整列・プリフェッチマクロを使いますが、実行時に SIMD は必須ではありません。

## ソースの推奨読書順

1. 乗法と `norm` —— 設計全体がこの積です。
2. `exp` / `log` / `sqrt` —— `system` が解析をどう変えるか。
3. `cos` のあと `sin` —— 還元恒等式。
4. `invert` のあと `acos` / `atan` —— 逆三角がこの形になる理由。
5. `scomplex.c` のエラー経路、`scomplex.hpp` の throw、`Scomplex.hs` の `throwError`。
